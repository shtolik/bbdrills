# bbdrills (drills.my): instructions for coding agents

Workspace rules, start and stop procedure: read `../AGENTS.md` first. Before ending a session, update the **Now**
section of `docs/handoff.md`.

Static, data-driven site of short off-season basketball drills (LePy coaching staff's drill list) with a compact
preview, a link to the YouTube video and local progress tracking. Live at https://drills.my (GitHub Pages,
`site/CNAME`).

## Layout

| Path | What |
|---|---|
| `site/` | the published static site: `index.html`, `drill.html`, `locales/`, icons, `sitemap.xml`, `robots.txt` |
| `site/default_drills_with_meta.json` | canonical drill manifest (used by the site and the tests) |
| `drills.md` | human-editable table of the same drills |
| `site/previews/` | MP4 previews (H.264, 25 fps) and single-frame WebP posters |
| `src/site/` | Preact app: `App.tsx` (cards, theme/lang/filter, modal, lazy loading), `main.tsx` (mount + YouTube API), `i18n.ts`, `url.ts` (deep links) |
| `src/lib/progress.ts` | progress persistence in localStorage |
| `site/site.bundle.js` | generated by `npm run build` (esbuild), git-ignored |
| `tests/unit/` | vitest; `tests/*playwright.spec.ts` | Playwright e2e (static server on port 8000) |
| `tools/` | git-ignored local binaries (`tools/yt-dlp.exe`, `tools/ffmpeg/bin/ffmpeg.exe`) plus tracked `tools/scripts/` |
| `copilot.md`, `plan.md` | earlier Copilot run log and the feature plan (sets/reps, diary, gamification) |

## Commands

```bash
npm install                 # after every branch switch
npm run build               # typecheck + bundle site/site.bundle.js
npm run test:unit           # vitest
npx playwright test         # e2e; starts npx http-server on :8000 (reuses a running one locally)
npm run format:check        # prettier; CI checks it on every push touching src/ or site/
```

Perf tests are off by default: `PERF_TESTS=1 npx playwright test -g "performance: first two"`
(PowerShell: `$env:PERF_TESTS='1'; ...`).

## Rules

- Work on a branch and open a PR. A push to `main` deploys GitHub Pages (`deploy-pages.yml`) to the live site.
- Before pushing a branch that changes behaviour: `npm run test:unit` and `npx playwright test` locally.
- Git LFS is required (the pre-push hook fails without `git-lfs`). Large media goes through LFS; never commit large
  binaries without asking the owner.
- Media names: `<drill-id>_<youtube-id>.<ext>` (e.g. `hip-airplane_URY-escJjss.mp4`); manifests resolve local
  files by that pattern. Previews: MP4 25 fps, 320 px wide, plus a WebP poster.
- Never change `gif_start`/`gif_end` (preview ranges) automatically; the owner sets them by hand.
- When adding a local video, update both `local_video` in the manifest and `drills.md`.
- Manifest fields: `id, name_en, name_fi, group_fi, group_en, local_video, video_url, details, video_length (s),
  gif_start (s), gif_end (s), sets, reps` (+ preview fields). Durations are integer seconds.
- UI state lives in localStorage `bbdrills_ui_v1` (language, theme, filter); progress in `bbdrills_progress_v3`.
  Keep migrations (`tests/unit/migration.spec.ts`) when changing the schema.
- Playwright: keep perf tests env-gated; mark absent UI as skipped (`test.info().skip()`), never swallow wait
  failures; in CI start a fresh server, locally reuse one; CI calls `./node_modules/.bin/playwright`, not `npx -p`.
- Respect content owners: videos are public YouTube links; remove previews if a rights holder objects.

## Commits, PRs and review replies

- Conventional subjects (`feat(site): ...`, `fix(...)`, `ci:`, `test:`, `chore:`); Markdown bodies with real
  newlines, never literal `\n` (write long bodies to a file and pass `--body-file`).
- Addressing review comments: one focused commit per comment, push them together, then reply on each review thread
  (inline, as a PR review, not as issue comments) with one sentence and the commit SHA.
- Remotes: `origin` (GitHub `shtolik/bbdrills`). No n40l backup yet.
